Analog proof the same actions, driving something

Thrust and turn are read with getActionStrength(), not isActionPressed(). On a keyboard they are 0 or 1 and the ship snaps; on a stick or trigger they are continuous and it eases. Same action, same code path.

Event stream raw pointer/touch vs. compat mouse

A clean TAP of the primary finger synthesizes the classic sequence after touchend: pointerdown → touchstart → pointerup → touchend → mousedown → mouseup → click. A drag past the ~10 px slop synthesizes nothing — the amber rows below are the synthesized ones.

Gestures gesturestart / gesturechange / gestureend

Pinch to zoom, two-finger drag to pan, two-finger twist to rotate. SDL3 has no gesture subsystem, so bro recognises these engine-side from the two oldest live contacts and dispatches WebKit-style gesture events alongside the untouched pointer stream. e.scale and e.rotation are relative to gesturestart, so the viewer multiplies onto a base captured there.

No touchscreen? Drag to pan, wheel to zoom, Shift+drag to rotate — a separate mouse path, not synthesized gestures.

Document-wide recognition: the founding pair is the two oldest live contacts anywhere in the document, and the events go to the hit target of their centroid. Leave two fingers resting on the visualiser panel and this map goes inert — those contacts founded the gesture, so it was delivered there. There is no per-element gesture arena.

IME composition compositionstart / update / end

An IME composes rather than types. The preedit is provisional text that is already in .value but is not real input yet — only compositionend is. Note bro dispatches composition events after the mutation, so the value shown by compositionstart already carries the first chunk.
