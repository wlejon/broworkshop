HarfBuzz shaping bro.text.shape() — ligatures, kerning, spacing, the cache

Every string in bro goes through HarfBuzz and comes back as a ShapedRun: a glyph array plus a cluster map from source bytes to glyphs. The map is the whole public contract — glyph ids never leave bro::render — and it is what makes the difference between shaping and a per-character lookup measurable rather than merely visible. The header of src/render/shaped_run.h puts it bluntly: with shaping, "prefix measurement is wrong by construction".

Font families found on this machine

There is no font-enumeration API in bro, so presence is inferred by measuring: a family that resolves to the same face as a deliberately nonexistent name was not found. Reported, never silently skipped.

Ligatures — n characters, one glyph

A cluster spanning more than one byte and producing exactly one glyph is a ligature by definition. Calibri is used here because, measured across the six families above, it is the only one that forms f-ligatures at default settings — an assertion written against Arial would prove nothing.

Kerning — the width of a pair is not the sum of its parts

The cheapest possible proof that shaping ran: kerning is a property of the pair, so any implementation that measures characters independently and adds gets a delta of exactly zero on every row.

Prefix measurement is wrong by construction

letter-spacing suppresses ligatures; word-spacing hits only spaces

CSS letter-spacing inserts space between characters, and a ligature has fused several into one indivisible glyph — so a non-zero letter-spacing must turn ligatures off. It is a shaping input (it changes which glyphs exist) and lives in the cache key; the spacing amount does not, because it only repositions already-shaped output.

Bidi — UAX #9 bro.text.bidi() / bidiReorder(), cross-checked against shape() and against layout

Three things must agree for RTL text to be right: level resolution (bro.text.bidi), reordering (bro.text.bidiReorder, rule L2), and the shaper, which runs both internally and emits its cluster map already in visual order. This panel checks each against the others rather than against a hardcoded expectation — and then checks all three against the live layout with Range.getBoundingClientRect().

Resolved embedding levels, per code point

The glyph on top, the level it resolved to underneath. Levels come back one per code point; runs come back in UTF-8 bytes. Confusing the two is the easiest way to write a bidi test that passes on ASCII and fails on everything else.

Astral text and grapheme clusters

An emoji is 1 grapheme, 1 code point, 2 UTF-16 units and 4 UTF-8 bytes — all four numbers are the right answer to some question. The cluster map is what reconciles them: a caret may sit at a cluster's start or end and never inside it. bro steps by cluster, not by grapheme (this build has no UAX #29 data — see the comment in shaped_run.h), so sequences the font does not fuse show up here as more than one stop.

Multi-word strings — a second bug this lab found

Layout measures a text node word by word and adds the pieces, so every kern pair that straddles a space is lost. That is the same "prefix measurement is wrong by construction" failure shaped_run.h warns about, reappearing one layer up at word granularity. Measured live, with the decomposition that proves the mechanism rather than just the delta.
