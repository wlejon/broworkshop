State machine

Graph

The lit node is node.state. Click any state to travel() to it manually — that follows the same authored transition the parameters below fire automatically.
Every transition carries its own fade; sync is syncPhase (the incoming cycle starts at the outgoing one's phase, so a crouch mid-stride keeps its feet), auto is autoAdvance (the engine leaves the state by itself when its one-shot clip ends).

Parameters

These name no state at all — they move a number and a boolean. Push speed past 0.05 and watch idle → move fire; tick crouch and watch move → moveCrouch. bro's machine has no condition language by design: the engine owns the graph, the app owns the decision, and this slider is that decision.

Transitions

onStateChanged(from, to), timestamped on the virtual clock. A jump logs two lines — the wildcard in, then the auto-advance back out — which is the machine driving itself with no JS in the loop.
Root motion

Drive the node from the clip

Switch this on with the speed up. Off, the character treadmills on the pad forever: the gait's displacement stays in the pose and the node never moves. On, setRootMotion pulls that displacement out of the blended pose and consumeRootMotion() hands it to the app, which walks the node down the marker run — 1.5 m per block. Same clips, same speed, same state machine. The animation is the source of truth for distance, so the feet never slide.
Cameras

Camera nodes

scene.createCamera() makes the camera a NODE: only the projection lives on it, the view IS its world transform. follow is parented to the character and never touched again — switch on root motion and it rides the hierarchy down the run with zero per-frame JS, which is the one thing the imperative setCamera path cannot do. Cinematic flies the wide camera from a createAnimationPlayer clip — the node-property tier animating a camera while the skeletal tier animates the character.
Clips

Library

Each button is play(name) with the current loop flag and speed — a hard cut, no fade. This suspends the state machine (a manual play takes the base track over and node.state goes null); travel to any state above to re-enter. Every clip is generated keyframe data compiled to a bromesh Animation; the engine evaluates it in C++.

Transport

stop fades the player out to bind pose and deactivates it — that is the T-pose you see, not a bug. Speed goes negative: the gait runs backward. Scrubbing writes animationTime, which re-poses immediately even while paused.
Crossfade

Blend into a clip

The outgoing clip keeps advancing while it fades, so walk → run stays foot-aligned instead of snapping. Set fade to 0 and hit the button to feel the difference a crossfade makes. A state-machine transition is this same machinery, with the fade authored into the graph instead of picked here.
Blending

Base mix

Blend space on the base track

A blend space is a base-track citizen: these are play(spaceName), the same call the clip grid makes. Clip buttons above take the base back.

1D — speed axis

One scalar picks the mix of idle@0 → walk@1.6 → run@5.0. The two neighbouring clips blend by position, and all members share one normalized phase, so the feet stay aligned at any mix rather than sliding.

2D — direction

Drag the pad — or hit a preset. X is strafe, Y is forward/back, with idle at the centre. The three nearest sample points blend by inverse-squared distance, so a corner is a genuine three-way mix, not a lerp along an edge.
Layers

Masked layers 0/3

Walk and wave at once. Put the 2D or 1D space on the base, push the speed up, then switch on slot 1 — the legs keep coming from the blend space while the arms come from the layer. The three rows default to disjoint masks (right arm / left arm / head), so all three can run over the gait simultaneously. Change a mask to full body and the layer swallows the walk entirely: that is the mask doing its job, in reverse. Layers survive a state transition — they never suspend.
Rig

Skeleton

The overlay reads getBoneWorldMatrix() per bone per frame and parks a marker there — the same seam a prop socket or a ragdoll would attach through. Those matrices are MODEL space, so the markers are parented to the character node and the engine composes its transform: the overlay stays glued to the rig even while root motion walks it away. Turn the mesh off to watch the rig alone.
